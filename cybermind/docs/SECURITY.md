# CyberMIND — Security Architecture & AI Safety

## 1. Defensive Boundary Guarantees
- **Simulated Execution Only:** CyberMIND never executes arbitrary shell commands generated by an LLM and never attempts offensive actions against real external targets.
- **Strict Read-Only Digital Twin:** What-if simulations (e.g. "Make API-01 Public") operate in-memory on cloned graph representations and never alter production configurations.

## 2. Authentication & Authorization
- **Argon2 / BCrypt Password Hashing:** Direct salted cryptographic password derivation.
- **Role-Based Access Control (RBAC):** Strict policy enforcement for `ADMIN`, `ANALYST`, and `VIEWER`.
- **JWT Cryptographic Verification:** HMAC-SHA256 signed access tokens with 24-hour expiry.

## 3. Blockchain Evidence Provenance
- **Zero Sensitive Data On-Chain:** Passwords, PII, and raw logs are strictly kept off-chain.
- **SHA-256 Merkle Anchoring:** Immutable timestamps and hashes prove tamper-evident chain of custody.
- **Verification Engine:** Cryptographic re-evaluation detects unauthorized modification immediately (`INTEGRITY_MISMATCH`).

## 4. AI Safety & Injection Mitigation
- **Untrusted Input Isolation:** Log lines, network payloads, and retrieved RAG context are labeled as untrusted data.
- **Adversarial Reviewer Agent:** Every multi-agent response is validated by a dedicated reviewer for hallucinations, unsupported claims, and ungrounded statements.
